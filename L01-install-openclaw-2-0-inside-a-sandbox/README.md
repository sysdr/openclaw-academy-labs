# Lesson 01 - Install OpenClaw 2.0 inside a sandbox (Docker or VM)

**Goal:** run the OpenClaw Gateway inside a hardened Docker container so everything the agent can touch is inside a box you control.

**Proof:** `make verify` prints `11/11 PASS`, ending with the agent answering a fresh one-time token from inside the sandbox.

Verified on OpenClaw **2026.10.4** (the "OpenClaw 2.0" release line; OpenClaw uses calendar versions), Docker Engine 29.8, Compose v5.5. See `VERIFICATION.md` for every command and its source.

- Code: https://github.com/sysdr/openclaw-academy-labs-p/tree/main/L01-install-openclaw-2-0-inside-a-sandbox
- Article: OpenClaw Academy, Lesson 01 (https://openclawacademy.substack.com)

## Quickstart

```bash
make bootstrap                      # Docker, Compose v2, python3, free port
make setup                          # creates .env; add OPENAI_API_KEY there, then rerun
make build && make run              # pull pinned image, start, wait for ready + healthy
make verify                         # 11/11 PASS
make test                           # unit + mock end-to-end (+ integration if image present)
```

## Files

- `Makefile`: one target per script below.
- `docker/compose.yaml`: the sandbox. Loopback-only port, all capabilities dropped, no-new-privileges, memory and PID limits, no Docker socket.
- `config/exec-approvals.json5`: exec policy `deny` (the agent can talk, not run commands).
- `scripts/lib.sh`: shared helpers (compose wrapper, PASS/FAIL checks, readiness waits).
- `scripts/bootstrap.sh`: host prerequisites. Lesson 01 has no previous lesson to rebuild.
- `scripts/setup.sh`: `.env` with a generated Gateway token, headless onboarding, exec policy.
- `scripts/build.sh`: pulls `ghcr.io/openclaw/openclaw:2026.10.4`, validates compose, prints the digest.
- `scripts/run.sh`: starts the Gateway, waits for `/startupz` 200 and Docker `healthy`.
- `scripts/verify.sh`: the 11 checks behind the proof; writes `reports/verify-<time>.txt`.
- `scripts/test.sh`: unit tests, mock end-to-end, shellcheck, integration.
- `scripts/demo.sh`: 60-second walkthrough.
- `scripts/clean.sh`: stops containers; deletes `state/` and `.env` only if you type `yes`.
- `src/l01_checks.py`: pure parsers for `docker inspect`, `docker port`, approvals and agent JSON.
- `tests/test_checks.py`: unit tests against `fixtures/cases.json` (captured real outputs).
- `tests/e2e_mock.sh`: runs the real `verify.sh` against `tests/mock/docker` and `tests/mock/curl`, passing and failing.
- `tests/integration.sh`: full stack with the real image and `tests/fake_llm.py` (offline model, no API key).
- `tests/compose.fake-llm.yaml`: overlay that adds the fake model on the compose network.
- `expected/verify.txt`: exact check lines for the pass and fail states.
- `solution/`: read-only root filesystem assignment.
- `.env.example`: placeholders only. `.env` and `state/` are git-ignored and stay on your machine.

## Credentials and their scope

- `OPENCLAW_GATEWAY_TOKEN`: generated by `make setup` (32 random bytes), stored only in `.env` (mode 600). It authorizes operators of this one Gateway. Never reuse it elsewhere.
- `GEMINI_API_KEY` (or `GOOGLE_API_KEY`): Google AI Studio key from https://aistudio.google.com/apikey. Use a dedicated project key with a spending limit. Onboarding stores a reference to the environment variable, not the key itself (`--secret-input-mode ref`). Default auth choice is `gemini-api-key`.
- Other providers: set `OPENCLAW_AUTH_CHOICE` to a value listed by `openclaw onboard --help` (e.g. `openai-api-key`) and add that provider's key variable to `.env`.

## Safety notes

- The host port is bound to `127.0.0.1`. Do not change it to `0.0.0.0` or remove the prefix; Docker publishes to all interfaces by default and bypasses ufw.
- Do not mount `/var/run/docker.sock` into this container. That is root on your host.
- `state/` holds agent config, sessions and provider auth in SQLite. Treat it and its backups as credentials.
